# Planner Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Cue proposes timed 1-hour study blocks inside the student's study times before each exam and assignment, and the student accepts, moves or rejects them on a three-day time grid.

**Architecture:** A new server subsystem in `server/src/planner/` (settings repository, pure time-zone helpers, a replaceable `PlanningStrategy`, a pure trimming rule and `PlannerService`) re-plans whenever `ScheduleService` announces a change (Observer). The Schedule Manager stores the blocks in `study_blocks`; suggestions are saved, not recomputed on each read. The app's Week screen becomes a three-day time grid with a block sheet, plus a Study times screen.

**Tech Stack:** Node 22+, Express 5, better-sqlite3, zod, Vitest + supertest (server). Expo SDK 58 / React Native 0.88, Jest + jest-expo, react-test-renderer (app). No new dependencies: time zones use the built-in `Intl` API.

**Spec:** `docs/superpowers/specs/2026-11-17-planner-design.md` (mockup: `docs/superpowers/specs/2026-11-17-planner-mockup.html`, option B)

## Global Constraints

- Work on branch `planner` from `main`. Never commit to `main`.
- Server: TypeScript ESM, relative imports end in `.js`. Check with `npm run typecheck && npm test` in `server/`.
- App: must keep running in Expo Go SDK 58; no new native modules. Check with `npx tsc --noEmit && npx eslint . && npm test` in `app/` (eslint: 0 errors; existing inline-style warnings are fine).
- Instants are stored as UTC ISO strings (`normalizeDate`). Study times are local `HH:mm` in the student's IANA time zone.
- Defaults (spec §5): exam 360 min, assignment 120 min, block 60 min, daily limit 180 min, lead 10 days (exam) / 5 days (assignment), study times Mon–Fri 18:00–22:00, Sat–Sun 10:00–16:00.
- Study time per item: 0–2400 min in steps of 60 (0–40 h). Daily limit: 60–720 min in steps of 60. A study range is 1–12 h long; an end earlier than the start means the next day.
- The only new personal data is the time zone and the study times.
- No sprint numbers ("Sprint 1", "sprint 2", …) in code, tests, comments, docs or commit messages. Describe features by what they do.
- Errors use `{ error, message }`. New code: `block_move_invalid` (HTTP 409).
- Each subsystem touches only its own tables through its repository. The Planner reaches schedule data only through `ScheduleService` methods.

## Review Focus

1. **Every study day switched off:** no blocks, a shortfall for every plannable item, no crash. Covered by Task 4, `plans nothing when every day is off`.
2. **A deadline less than an hour away, or today's study time already passed:** no block before now, and the shortfall is reported. Covered by Task 4, `never plans before now, even when the deadline is today`.
3. **A Canvas re-sync or an edit moves a due date earlier than some accepted blocks:** those blocks are removed and the earlier ones stay. Covered by Task 8, `drops accepted blocks that end after a moved deadline`.
4. **The student travels and the time zone changes:** suggestions move to the new local study times, and accepted blocks keep their absolute times. Covered by Task 7, `re-plans in a new time zone and keeps accepted blocks`.
5. **Acting on a block that a re-plan already replaced (a stale id):** the server returns 404 `not_found`, and the app shows a message and reloads. Covered by Task 8, `rejecting a block that a re-plan replaced is a 404`, with the app side going through `mutate` in Task 12.

- `zonedTimeToUtc(localDate: string, time: string, timeZone: string): Date`. `localDate` is `YYYY-MM-DD` and `time` is `HH:mm`. A wall-clock time that occurs twice (fall back) gives the earlier instant. A wall-clock time that is skipped (spring forward) gives the instant one hour later.

- `minutesOf(time: string): number`, for example `"18:30"` → `1110`.

### Task 4: The planning strategy (pure)

**Files:**
- Create: `server/src/planner/config.ts`, `server/src/planner/types.ts`, `server/src/planner/DefaultStrategy.ts`
- Test: `server/test/strategy.test.ts`

**Interfaces (Produces), `types.ts`:**

```ts
export interface StudyWindow { weekday: number; enabled: boolean; start: string; end: string }
export interface PlannerSettings { timeZone: string; dailyLimitMinutes: number; windows: StudyWindow[] }
export interface Interval { startsAt: string; endsAt: string }
export interface BlockRef extends Interval { itemId: string }
export interface AcceptedBlock extends BlockRef { id: string }
export interface PlanItem {
  id: string; title: string; kind: "exam" | "assignment";
  dueAt: string | null; studyMinutes: number; done: boolean;
}
export interface PlanInput {
  now: Date; settings: PlannerSettings; items: PlanItem[];
  busy: Interval[]; accepted: AcceptedBlock[]; rejected: BlockRef[];
}
export interface Shortfall { itemId: string; itemTitle: string; dueAt: string; neededMinutes: number; plannedMinutes: number }
export interface PlanResult { proposed: BlockRef[]; shortfalls: Shortfall[] }
export interface PlanningStrategy { plan(input: PlanInput): PlanResult }
```

**`config.ts`:** `export interface PlannerConfig { studyMinutes: { exam: number; assignment: number }; blockMinutes: number; dailyLimitMinutes: number; leadDays: { exam: number; assignment: number }; windows: StudyWindow[] }` and `export const PLANNER_DEFAULTS: PlannerConfig`, holding the Global Constraints values. Windows are indexed by weekday 0–6.

**`DefaultStrategy implements PlanningStrategy`**, `constructor(config: PlannerConfig = PLANNER_DEFAULTS)`. This is the algorithm the spec leaves open; implement it as written:

```
slots: for each local date d from addDays(localDateOf(now), −1) (so last night's range past midnight counts) to the latest due date's local date:
  w = window for weekdayOf(d); skip if !w.enabled
  start = zonedTimeToUtc(d, w.start); end = zonedTimeToUtc(minutesOf(w.end) <= minutesOf(w.start) ? addDays(d,1) : d, w.end)
  cut [start, end) into blockMinutes slots from start; each slot's study day = d
study day of an accepted block = the window day whose range contains its start, else localDateOf(start)
dayUsed[d] = minutes of accepted blocks on study day d
plan items where !done && dueAt && dueAt > now, ordered by dueAt, exams first on ties:
  needed = ceil((studyMinutes − accepted minutes of this item) / blockMinutes); skip if <= 0
  usable(slot) = slot.start >= now && slot.end <= dueAt
              && no overlap with busy, accepted (any item) or proposed so far (any item)
              && no overlap with this item's rejected blocks
              && dayUsed[slot.day] + blockMinutes <= dailyLimitMinutes
              && this item has no accepted or proposed block on slot.day
  days = study days >= addDays(localDateOf(dueAt), −leadDays[kind]) that have a usable slot, ascending
  if days.length < needed: days = all study days that have a usable slot, ascending
  n = min(needed, days.length); last = days.length − 1
  picked = n === 1 ? [last] : k = 0..n−1 → last − round(k · last / (n − 1))
  in each picked day take its earliest usable slot (update proposals and dayUsed)
  if n < needed: shortfall { neededMinutes: studyMinutes, plannedMinutes: accepted minutes + n · blockMinutes }
result.proposed is sorted by startsAt, then itemId; shortfalls in planning order
```
